# tutor-app — notes for agents and future sessions

## This is NOT the Next.js you know
This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` before writing any code. Heed deprecation notices.

## What this is
A live voice tutor for students in grades 5–12 with a shared whiteboard. The student talks; the tutor talks back and writes on a tldraw canvas as it teaches. Brand working name: Chalk. `PRODUCT.md` is the design brief.

## Stack
- Next.js 16 App Router, React 19, TypeScript, Tailwind v4 (CSS-first, tokens in `app/globals.css`).
- Voice: **OpenAI GPT-Live-1** over WebRTC (`gpt-live-1`). Teaching brain: a Responses model via GPT-Live "Responses delegation" (`gpt-5.6-terra` by default).
- Voice fallback: **Gemini Live** (`gemini-3.1-flash-live-preview`, one model talks and draws) behind the same client surface; picked per session, see "Voice provider switch".
- Board: tldraw v5 + KaTeX (`components/TldrawCore.tsx`, `lib/semantic-board.ts`).
- Auth: next-auth v5 (JWT). DB: Neon Postgres via Drizzle (`lib/db/schema.ts`). Route protection in `proxy.ts`.

## Architecture (branch `gpt-live`, Sept 2026)
- `app/api/live-session/route.ts` — POST with the browser's SDP offer. Loads the student's profile and memory notes, composes both prompts, registers the whiteboard tools with the backend, calls `client.live.create`, returns the SDP answer plus the greeting/resume lines. The OpenAI key never leaves the server.
- `lib/live-tutor.ts` — browser client: mic track + `oai-events` data channel, transcript assembly, backend tool loop, speaking meter (RMS on the remote track), reconnect-with-history on drop.
- `lib/live-events.ts` — pure reducers (`TranscriptAssembler`, `BackendTurnTracker`), unit-tested.
- `lib/tutor-prompts.ts` — the prompts, built from named sections. Voice model: persona, speaking style, backchannel, interruption, delegation, boundaries. Backend: output contract, then the teaching sections (see "How the tutor teaches"), the whiteboard section, the student profile and memory, files/safety/reconnect, and eight teaching-moment examples. Gemini gets the conversation sections minus delegation, plus the same teaching sections.
- `lib/whiteboard-tools.ts` — the tool declarations (single source of truth) and `WHITEBOARD_FUNCTION_TOOLS` (Responses format). `lib/whiteboard-tool-dispatch.ts` validates arguments, calls the board handle, and returns a result that describes the picture ("Drew 1 circle cut into 2 equal parts, 1 shaded"); the session page appends a `[Board: …]` summary so the backend knows what the student sees.
- `lib/board-diagrams.ts` — pure, unit-tested math and parsers behind the picture tools (fractions, tick steps and fraction labels, intervals/jumps syntax, figure vertices and label placement, sketch strokes). `components/TldrawCore.tsx` turns the parsed inputs into tldraw shapes.

- `app/api/profile/notes/route.ts` — durable tutor memory (`user_profiles.tutor_notes`), written by the `remember_about_student` tool and loaded into the backend prompt at session start.
- Voice previews are gone (Sept 14): the old `app/api/voice-preview` route played OpenAI TTS, which failed once the account ran out of credits and never matched the Gemini voice a session actually uses.
- `app/session/[id]/page.tsx` — session orchestration and persistence (transcript events, board snapshots, heartbeat, pause/resume).

## How the tutor teaches (Sept 15 2026)
- The prompt follows the tutoring research in the "How Chalk Should Teach" review (expert tutors, Bridge, Tutor CoPilot, worked examples and fading, feedback research). Teaching comes before the board in the prompt: "What you are for", "How every turn works" (classify the move, decide what they need, end with something for the student to do), "Reading the student's answer" (correct/unsure/slip/wrong idea/partial/guess, and never call a wrong answer right), "How much help" (levels H0 wait → H5 worked example then fade; novices start high, students who are getting it start low), "Feedback and praise" (praise the move, flag mistakes indirectly), "Adapting up and down" (feelings first, confusion is not an emergency, raise the challenge when they cruise), "The session" (warm-up from notes, reflection after a solve, closing check and "Today's rule"), "When they want the answer" (a worked parallel problem as the fair fast path).
- Removed on purpose: "EVERY reply includes at least one board action", "start as high on the hint ladder as you can", immediate cross-outs of wrong answers, and repeated example openers ("Totally fair"). Onboarding slider preferences now appear only as "Stated preferences (a soft default; trust what you see them do over this)", and only when set.
- Gemini used to lose the backchannel, interruption, and boundaries rules (the persona was sliced at "# Backchannel policy"). Fixed; a unit test guards it.
- **Tutor tools and policy (Sept 15 2026; merged Sept 16).** The app-owned tool lives in `lib/tutor-tools.ts`, declared apart from the whiteboard tools and added next to them in `gemini-live.ts` (setup), `app/api/live-session/route.ts` (Responses tools) and `scripts/eval-tools.ts`. `check_answer(problem, student_answer, skill, help_level?, kind?)` runs `lib/answer-check.ts`, a deterministic checker on `math-expression.ts`: arithmetic, fractions, percent and "of", mixed numbers, simple LaTeX, implicit multiplication, one letter renamed to x, linear and quadratic equations (it knows the solutions, so "3" for x² = 9 is `partial`), and expression equivalence by sampling. It returns correct / partial / incorrect / cannot_check, never guesses on ambiguous input ("3 4", two letters, inequalities), and may give the right value "for you only". It also records the attempt in `lib/tutor-policy.ts` (`attemptFromVerdict`: correct, partial, `unchecked` for cannot_check, which counts neither way, and for a wrong answer the `kind` the tutor saw, slip, misconception or guess, else `incorrect`). A right answer's result asks for `circle_item` with keep=true, and for an equation, a check. `record_attempt` was merged in on Sept 16 2026: no recorded session had ever called it.
- The policy (pure, unit-tested, one instance per live client; replaces the old `tutor-state.ts`) keeps attempts, misses in a row, quick-right streaks, and signals read from whole student utterances (frustrated, confused, idk, bored, unsure; each counts for two utterances). It builds one line: `[Tutor state: skill "adding fractions": 0 of 2 right · 2 misses in a row (last: stuck) · suggested help H3 (2 misses in a row) · down: sounds frustrated (…) · 9 min in. Not from the student; never read it aloud.]`. Tutor tools always answer with it; board tool results carry it only when it changed (`takeStateUpdate`). Nothing is injected as an extra model turn any more (the old Gemini downshift made the tutor speak again after its turn). Gemini collects input-transcript fragments and reads the utterance once the tutor answers or calls a tool; GPT-Live reads flushed student utterances and typed text. Attempts are session-only for now.
- The prompt says: call check_answer before calling an answer right or wrong, with the skill and the kind of mistake when you can tell, and follow the suggested help level unless what you see says otherwise; the examples show it. `lib/tutor-tools.test.ts` fails if a prompt example names a tool that is not declared.
- **The teaching loop around the tools (Sept 16 2026).** Recorded sessions judged 20+ answers by eye, did arithmetic out loud that never reached the board, saved nothing to memory, opened "Problem 8" when the student said "part c", and left cancelled drawings on the board. What changed:
  - **Nudges** (`lib/tutor-policy.ts`, each carried once by the next board result through `boardResultExtras`, in both clients and the evals): an answer-shaped student line nobody checked ("[Unchecked answer: … call check_answer]"), arithmetic said in a turn that drew nothing ("[Said, not written: …]", from `spokenMath` in `noteTutorTurn`), memory due after a first misconception or when the student says goodbye with nothing saved, and every six results or three minutes the uploaded files ("[Files: File 1 "sheet.pdf" (3 pages). … call look_at_worksheet first …]").
  - "I don't know" while a skill is going is recorded as a `stuck` attempt with no tool call (`isNonAnswer` plus the idk signal). `cancelAttempt(callId)` takes back what a cancelled `check_answer` recorded.
  - **`look_at_worksheet(file?, page?)`** (`lib/session-tools.ts`, a third tool family next to board and tutor tools): the page shows the chosen page again as a picture, spaced at least a second from board frames, then answers "Here is File 1 "…", page 2 of 3". `resolveWorksheet` picks the file by label or name words and remembers the last page.
  - **`look_at_board`** now sends its picture before it answers (it used to answer first, so the tutor described an older picture), waits at most 2.5 s for the writing to finish, and says "The board is empty." when it is.
  - **Tool calls in Gemini Live** run on their own queue (audio keeps flowing), may be async, and are capped at 3 s: every tool blocks 3.1 Flash Live until it answers. `toolCallCancellation` reaches `onToolCancelled`: the page calls `undoCall(callId)` (below) and records `tool.cancelled`; a response for a cancelled call is dropped.
  - **Undo** (`TldrawCore.undoCall`): every shape a call draws carries `meta.callId` (through `withDirectMeta`), items and queued jobs carry it too. Undo drops the call's queued writing and marks, deletes its shapes and items, reverts line marks it set (`mathChangesRef`), and for `start_new_problem` puts back the board it cleared (`clearedBoardsRef`, the last three). `/dev/board?demo=cancel` runs all four cases (calls are `c0`, `c1`, … by position; a `__undo` step takes one back).
  - New client surface (`TutorClient`): `sendImageFrame(dataUrl, caption?)` and `sendStudentEvent(text)` (a user turn, for Explore in Phase 9); `LiveTutorCallbacks.onToolCall` gets the call id and may return a promise.
- **The prompt, rewritten around the board (Sept 17 2026).** What the recorded sessions got wrong is now written as rules in `lib/tutor-prompts.ts`, and `tutor-prompts.test.ts` checks each one is there:
  - **Teaching.** After a guess, "I don't know" or "what?", the tutor never answers its own question. "What?" usually means the student lost the question, so it asks again in fewer words. "I don't know" means make it smaller: two choices, a picture, or the first step done. The closing never ends on "I don't know".
  - **Board rules.** `boardSection(desmos)` now opens with four rules. Rule 4: what you work out goes on the board in the same reply (the problem as printed, the formula with its numbers, each step you say, the check), their right answer is ringed with `circle_item` keep=true, labels carry units, and nothing that gives the answer away is written before they say it.
  - **Board moves.** For a worksheet, call `look_at_worksheet` first. Attempts are the student's exact words. Every mark is the one sky pen. Leave `place` out. Callouts hold prompts; praise and chat are said, not written.
  - **Routing.** With Desmos, anything on a coordinate plane goes to `draw_desmos`: expressions, points, polygons, sliders like `m=2:-5..5`, and an empty grid (only the bounds). Data goes to `draw_data_plot`, categories to `draw_bar_chart`, values to `add_table`. `draw_figure` draws numeric lengths to scale, and grid=true lets the student count squares.
  - **Without Desmos.** When `desmosConfigured()` is false (a production build with no key), the prompt keeps the old `add_function_graph` / `plot_points` / dot-plot lines. Both builders take `PromptOptions { desmos?: boolean }`, defaulting to `desmosConfigured()`.
  - **Examples.** In `examplesSection(desmos)`, Example 5 is a right answer: `check_answer`, the attempt, a kept ring, and a two-line `draw_desmos` (`draw_equation_step` without Desmos). Example 9 is "what?": point at the item and ask a smaller question.
  - **`add_callout`.** It keeps a question that follows a praise sentence (`withoutPraise` in `lib/board-content-rules.ts`): "Exactly. What is 11 minus 3?" is written as "What is 11 minus 3?".
  - **Sizes.** The backend prompt ceiling is 19,600, up from 19,200. With the test profile the backend prompt measures 19,594 after Explore's clause (19,574 before it; an earlier note said 19,543, which was stale), six under the ceiling, so the next rule has to pay for itself. The Gemini prompt has its first ceiling, 20,800, and measures 20,692. Without a profile: backend 19,300 (18,951 without Desmos), Gemini 20,352. The whiteboard tool schema went from 41 tools at 44,085 characters to 37 at 38,815, under the 39,000 test.
  - **Eval.** `board-eval --set sessions` (flash-lite, 6 scenarios × 6 turns), Sept 16 baseline → Sept 17:

- Still not built (planned in the review): a learner model that persists skills and session summaries across sessions, a student pen on the board, Gemini VAD/thinking tuning, onboarding changes.
- **Teaching eval.** `npx tsx scripts/tutor-eval.ts [--persona misconception,anxious] [--turns 6] [--tutor gemini-3.5-flash] [--student gemini-3.5-flash-lite] [--judge gemini-3.8-flash] [--out file.json] [--verbose] [--prompt path]`. `--prompt` loads another copy of `tutor-prompts.ts` (for example `git show HEAD:lib/tutor-prompts.ts > /tmp/old/tutor-prompts.ts`) so two prompt versions can be compared on the same students. So on the free tier the eval runs roughly one persona a day; an old-vs-new comparison needs billing on the key. The script fails fast on both quota errors instead of waiting. Simulated students are too agreeable (they drop wrong ideas easily), so treat the numbers as a comparison between prompt versions, not a measure of real learning.

## The board (Sept 2026 rebuild)
- Picture tools, all rendered from real tldraw shapes: `draw_fraction` (pie or bar, improper fractions get extra wholes, typeset "= 3/4" beside the model), `add_number_line` (step, fraction tick labels, dots, shaded intervals with open/closed ends and rays, hop arrows), `draw_figure` (triangle, right triangle, square, rectangle, circle with side/vertex/angle/radius/diameter labels), `draw_angle`, `draw_array` (with dashed group splits), `add_area_model`, `draw_balance` (equation as a scale), `draw_bar_chart`, `draw_sketch` (polylines in a 0–100 box, the escape hatch). `add_function_graph` and `plot_points` draw real graphs (see "Graphs: Desmos"); nothing is a PNG any more.
- Style rules in `TldrawCore.tsx`: `INK` (black) for structure, `PENCIL` (the custom `pencil` colour, #5b5b66, 6.9:1 on white where tldraw's grey was 2.4:1) for the student's attempts and captions, and a marker palette (`MARKERS`: blue, violet, green, orange, red) for the tutor's drawings. `takePens(n)` hands each new diagram, and each series inside one, the next pen, so two fractions, five bars or three forces never share a colour; the counter resets on `start_new_problem`. **Every tutor mark is sky** (Sept 16 2026, Mateo's call, so the board matches the app's `--lp-sky`): highlights, rings, underlines, boxes and the pointer use the custom `sky` colour (#3d9cff); strikes use `sky-deep` (#1d7ee6), because #3d9cff is 2.9:1 on white and a line through black text has to read; typeset lines use the same two (`MATH_CORRECT_HEX` / `MATH_WRONG_HEX`). The three colours are new names added through `TLThemeDefaultColors` in `components/board/board-theme.ts` and passed to `<Tldraw themes>`, so the diagram pens look exactly as before. Headings are sans; notes and student work are tldraw's handwriting face; diagram labels are sans. Box heights come from `measureText` (tldraw's own text measurer), never from character counts. Diagrams use solid strokes; only `draw_sketch` keeps the hand-drawn wobble.
- Typeset math is a real tldraw shape: `components/board/MathShape.tsx` (`type: "math"`, registered through `TLGlobalShapePropsMap`) renders KaTeX in an `HTMLContainer`, measures itself off-screen at creation (`measureMath`), and carries `annotation` (16 px board sans in #5b5b66 since Sept 16 2026, identical in `measureMath`, the view and `toSvg`; it was 13 px grey), `crossOut`, `highlight`, `reveal` (the writing animation) and `role` (`"label"` for the "= 3/4" captions beside fraction models, which `highlight_step` / `cross_out_step` skip). `toSvg` exports the line as plain text (`lib/latex-plain.ts`) with its cross-out and ring, so board pictures need no compositing. That export is what the tutor and the admin replay see, so a bug there blinds the tutor to its own board while the student sees correct KaTeX: until Sept 15 `\pm` matched the front of `\pmod` ("±od6"), `\equiv`/`\mid`/`\nmid` were stripped as unknown commands, and `\_` printed its backslash. `latex-plain.test.ts` now covers the cases real sessions produced. `createMath` in TldrawCore creates them; `mathOrderRef` keeps creation order for "newest line" lookups. Old snapshots with `eqItems` overlay records are turned into shapes on load. `.chalk-math .katex-display { margin: 0 }` keeps the box tight.
- Camera: `focusOn` treats "visible but zoomed out below 0.8" as not visible, so new content always comes back to a readable zoom (this is why the first drawing looked tiny when the student had zoomed out). Since the Sept 14 layout work it frames the whole board page when the page fits on screen at that zoom, so the board holds still while the tutor writes, and otherwise (phones) it frames the item's row from the page's left edge, so a row never loses its start off screen. Since Sept 16 2026 it plans one camera with `planCamera` (`lib/board-camera.ts`, pure, unit-tested) and sets it once, animated over 320 ms. It used to call an animated `zoomToBounds` and then clamp to 0.8; the clamp read the zoom before the animation had moved, and its own `setCamera` cancelled the first move, so the camera zoomed in place instead of travelling to the item, and a 390px phone sat at 0.55. A phone now lands at 0.8 in one move. A rect that fits at that zoom is centred, its padding shrinking first (Sept 17: a 420px graph kept its left padding and lost 16px on the right), and a lone item wider than the screen at 0.8 (a 560px number line) is framed whole with tight margins, down to 0.55. It is a no-op while a tool call is still drawing; `endItem` focuses once the drawing is placed.
- Backend prompt (`lib/tutor-prompts.ts`) has a board-first rule: one diagnostic question at most, then draw the picture in the same reply as the idea; never describe a picture in words or fake one with brackets; one to three board actions per reply. Examples B, B2, B3 show fractions, a sketch and the balance.
- **Board use, fixed Sept 15 2026** after measuring every recorded session (55 tool calls). What was wrong: two sessions had ZERO tool calls while the tutor said "Focus on the table on the board" and "On the board, I've drawn a triangle" (students answered about a blank board); 24 of 41 shipped tools had never been called once, `draw_figure` and `draw_sketch` among them; text containers were 47% of all calls against 20% real pictures. The tools were registered the whole time, so this was the model taking the cheap path, not a regression. Evidence and numbers: `project_board_use.md` in memory.
  - The board section now opens with **three rules that override the rest**: (1) the first reply on a new topic calls `start_new_problem` and draws it in the same reply, and a topic with no picture tool is still drawn (`draw_sketch`, `draw_figure`, `add_table`, `add_number_line`); (2) never mention board content that was not drawn; (3) words on the board are labels, not explanations. The ceiling in `tutor-prompts.test.ts` moved 19000 -> 19200 to pay for them (268 chars net after trimming the lines they replaced). Raise it again only for a rule that earns it.
  - **The caps are enforced in the dispatcher, not just described**: `add_text_note` 160 chars, `add_worked_example_box` 140 chars over at most 3 lines (`NOTE_MAX` / `BOX_BODY_MAX` / `BOX_BODY_LINES` in `lib/whiteboard-tool-dispatch.ts`). Over the cap the call is refused with the instruction ("say the explanation out loud, or draw the idea instead"), because the model ignores tool descriptions but reacts to tool errors.
  - `draw_sketch` is now the declared **fallback** for any topic without a picture tool, instead of a tool whose own description told the model to prefer others.
  - `sendInitialGreeting`'s "Do not start teaching until the task is identified" now carries the counterpart "the moment they name it, your first reply about it puts it on the board", and the resume instruction no longer says "do not use whiteboard tools until a concrete task is confirmed" (it kept the anti-hallucination half).
  - `scripts/board-eval.ts` scores two new things: **picture rate** (a real diagram, not another box of words) and **phantom board claims** (the tutor saying "on the board" when nothing was drawn that turn). Run it before and after any prompt change here.
- **Board content (Sept 16 2026).** A recorded session wrote 23 texts and 13 had a defect. `lib/board-content-rules.ts` (pure, unit-tested) now checks every text before it is written, and a refusal says what to do instead:
  - `boardLines`: a literal `\n`, or " | " between words, is a new line (a note printed "Point 1: (2, 3) | Point 2: (6, 11)" with its pipe). `splitSlots` keeps empty pipe slots, so `annotations: "| | take the square root"` lands on the third line; `splitSteps` splits a block on " | " so an absolute value survives.
  - `add_student_attempt` refuses non-answers in every session language (`isNonAnswer`: "i dont know", "what?", "no sé", "不知道"…), text about the student ("you said…"), and anything over 200 characters. A bare "no" is allowed: it can answer a yes-or-no question.
  - `add_callout` is one small sky tag sized to its words (at most 360 px and 120 characters; an old `style` is ignored). Praise ("Perfect slope calculation!") and chat without math ("Let's wrap up… Ready?") are refused (`calloutProblem`).
  - Duplicates: each call's content is fingerprinted into `ItemToken.content` and `BoardItem.content`. The same text since the problem started, the same line as the newest equation, or the same picture as one of the last six is not written again; the tool points at the item and says "Already on the board as b2".
  - `start_new_problem` answers "…(item b1). Next, write the problem itself exactly as given, then work under it." A follow-up sentence goes after the item id through the dispatcher's `NEXT` separator.
  - Right triangles take `side_labels` as 'bottom leg | upright leg | hypotenuse' (`figureSideLabels`; "6 | 8 | x" used to put 8 on the hypotenuse). Three numbers that only fit Pythagoras another way are moved, and the result says "legs 6 and 8, hypotenuse x".
  - Sketch labels (`placeSketchLabels`): a label that says rise or height sits beside the most upright stroke near it, one that says run, width or base under the flattest, and every label is pushed off strokes and off other labels.
  - The vector number line prints the value of every dot between ticks, in the dot's colour, and stacks labels that would collide into lanes (`labelLanes`). Table and area-model cells read like math ("x^2" shows as x²).
  - `latexToPlain`, which is what the tutor reads back from its own board, writes real superscripts and subscripts (x², x¹⁰, a₁, e⁻ˣ; x^(q) where Unicode has no form), ∛ for `\sqrt[3]`, and keeps function names (`\log_2 8` used to read "₂ 8"). `normalizeLatex` braces multi-digit powers (`x^10` set as x¹0) and leaves two-letter products in math (`y = mx + b` set "mx" upright). `normalizeForMatch` ignores `^`, `_` and braces, so `highlight(text: "x^2")` finds x².
  - Cut from the declarations: `add_two_column_comparison`, `add_vector_diagram` and `add_process_map` (gone), and `highlight_step`, `clear_whiteboard` and `add_coordinate_axes` (still replayed by the dispatcher for old recordings, scripts and the landing). The `column` parameter is gone from every tool; the dispatcher still reads it. The schema went from 43,513 to 35,748 characters (41 tools to 35), and `whiteboard-tools.test.ts` keeps it under 39,000. Dead handle methods went too: `drawShape`, `addStickyNote`, `addTwoColumnComparison`, `addVectorDiagram`, `addProcessMap`, `captureScreenshot`, `applyBoardActions`, and the no-op `ensureColumnRoom`.
  - `/dev/board?demo=content` replays all of it.
- **Free visual QA:** `npm run dev` then open `/dev/board?demo=fractions|algebra|geometry|data|all&step=300&count=N`. It mounts the whiteboard and replays scripted tool calls with no OpenAI session (`app/dev/board/demos.ts`). The route is dev-only (404 in production, public in `proxy.ts` only in development). ## Math only (Sept 14 2026)
Chalk tutors math and nothing else (arithmetic, fractions, decimals, percent, ratios, negatives, algebra, geometry, graphs, basic statistics). The prompts say so in the persona, a "# Math only" section, and the Gemini contract; the landing FAQ, onboarding examples, and debug panel match. The board section carries a topic playbook: which picture tool for which topic. Picture tools added for the math focus, all in `components/TldrawCore.tsx` with pure helpers in `lib/board-diagrams.ts`:
- `draw_tape_diagram` (bar model: rows of boxes, `*` shades a box, `= total`, a bracket for the grand total) for ratios, parts and totals, a fraction of an amount.
- `draw_grid` (rows × columns, first N shaded) for percent, decimals, fraction of a set, area as counting squares.
- `write_vertical` (stacked +, −, × with carries and partial products, right-aligned mono) and `draw_long_division` (bracket, quotient, step lines; leading spaces place digits).
- `draw_transversal` (two parallels and a transversal, angles 1–8 clockwise from upper left, `mark_angles` arcs).
- `draw_figure` grew parallelogram, trapezoid, rhombus, pentagon, hexagon, and 3D rectangular_prism / cube / cylinder (`side_labels` = dimensions), plus `height_label` (dashed altitude with a right-angle mark). Side labels are positional: "12 | | 6" skips the right side.
- `add_function_graph` grew `mark_points`, `slope_run` (a rise/run triangle), and `second_expression` (two curves, crossing point marked: systems of equations); `draw_array` grew `shaded`; `draw_angle` grew `adjacent_degrees` (angles on a line / around a point); `add_number_line` grew `label_style` (tenths read as decimals by default) and `second_min`/`second_max` (a double number line for percent of an amount); `plot_points` grew `connect` (join into a polygon).
- `draw_fraction` grew `common_denominator` (1/2 and 1/3 recut into sixths); `draw_grid` grew `shade_rows`/`shade_columns` (rows tinted, columns tinted, overlap in full colour: multiplying fractions); repeated number-line points stack into a dot plot. Note, callout, setup, and table results quote their content so the tutor can point at or erase them by what they say.

## The tutor's hands (Sept 14 2026)
- **Board items.** Every tool call is one item with a short id (`b1`, `b2`, …). `dispatchWhiteboardTool` wraps each call in `board.beginItem/endItem`; the id rides in the result ("… (item b7)") and `getBoardSummary()` returns the item list (`formatBoardItems` in `lib/board-items.ts`) that the page appends as `[Board: …]`. Items resolve by id, label words, kind, or `last` (`resolveItemTarget`, unit-tested). Item bounds measure rendered text and typeset math, not their wide layout boxes.
- **Pointer and rings.** The tutor is a tldraw collaborator: an `instance_presence` record (`userId: "tutor"`, sky) drawn by `components/board/TutorPenOverlay.ts`, which replaces two of tldraw's overlays: the collaborator cursor (a pen glyph and a name tag in #1d72dc, so its white text passes 4.5:1) and the collaborator scribble (`TutorScribbleOverlayUtil`; tldraw painted the laser ring at 10% alpha, invisible on a real board, and ours draws the presence colour at 70% and fades). `point_at` glides it onto an item with a small tap; `circle_item` draws that laser ring (presence `scribbles`, fades after ~3 s) or, with `keep=true`, a sky ring that stays. `erase_items` / `erase_older` delete items (shapes + typeset lines). The cursor hides after ~6 s idle.
- **Highlighter** (Sept 14 2026). `highlight(target, text?)` runs a real tldraw `highlight` stroke (drawn behind the ink) over the exact words in an item, e.g. `text="2x"` in an equation line or a tick label on a number line, or over the whole item. A drawing gets a slim marker ring instead: a highlighter ring smothered the drawing, and tldraw's highlight `scale` cannot thin it because its SVG export divides positions by the scale. Short words need care: tldraw's `getStrokePoints` drops points within a third of the stroke size of either end and skips the first three points until the stroke is a full stroke-size long, so a short, sparse swipe collapsed into a dot at its left end. Short swipes use 1px point spacing and a run of at least two thirds of the stroke size plus 4px (`swipePoints`). There is one colour, sky (Sept 16 2026: the four meaning colours are gone and an old `color` argument is ignored), so the tutor says what a mark means. A target taller than it is wide (a stacked fraction) gets a vertical swipe (`highlightSwipeFor`). The dispatcher checks the words synchronously (`normalizeForMatch` / `matchVariants` in `lib/board-items.ts`, which also match a typeset fraction whose DOM has no slash and puts the denominator first), so the tool result says honestly when it fell back to the whole item. The stroke is placed by measuring the words in the shape's DOM (`[data-shape-id]`, text-node ranges only so KaTeX's tall layout boxes never count, `.katex-mathml` skipped, math annotations skipped) and converting with `editor.screenToPage`; it queues behind the writing, joins the item (erased with it), and exports with board pictures. `highlight_step` is no longer offered (Sept 16 2026); `circle_item` with keep=true rings a whole line. `/dev/board?demo=highlight` replays it.
- **Written, not pasted.** `revealItem` hides everything a tool call created and a queue writes it in reading order with the cursor leading (`lib/board-reveal.ts` plans order and durations): text types out, strokes and lines grow point by point (original points kept in `strokePointsRef`), boxes and arrows fade, typeset math wipes in. The pace is an unhurried hand: about 20 characters a second, a 4.5 s cap per tool call, a pen glide and a short pause before each big piece (the Sept 14 speed was 1.8 s and read as rushed). `catchUpPace` speeds a call up only when tool calls are queued behind it. Pointing and rings queue behind the writing, and the queue always starts on a `setTimeout(0)` after the tool call returns (see the next bullet). `onWriting` keeps the dock badge on "Writing on the board" while the queue runs. Reduced motion skips the animation.
- **Marks are never items** (Sept 16 2026). A highlight ring once sat in empty space: with the queue idle, the highlight ran inside its own tool call, so `endItem` registered the mark as a new item and nudged it into free space. Now every tool has a role (`toolRole` in `lib/board-items.ts`: draw, mark, erase, look, memory), `endItem` registers and places only `draw` calls, and marks always run from the queue. When a mark runs it finds its target again, measures it without earlier marks (`meta.mark`) or the decorations beside it (`meta.decor`, e.g. the "you" tag on an attempt), draws, and joins the item, so erasing the item erases its marks. In development `checkMarkLanded` warns when a mark lands away from its target. Kept rings are superellipses that grow until they enclose the corners at any aspect ratio (`ringPoints`, tested from 1:1 to 20:1). `/dev/board?demo=rings` replays every kind of mark; run it at `&step=6000` too (the idle-queue case) and under reduced motion.
- **The tutor sees the board.** `exportImage()` waits for the queue, then renders the board to a JPEG (every shape exports itself; math shapes export as plain text with cross-outs and highlights). Exports are white like the board on screen: the board theme sets `background: "#ffffff"` (Sept 17 2026; tldraw's own #f9fafb framed every white Desmos picture in a faint box). The session page sends one to Gemini as a `realtimeInput.video` frame about 1 s after each tool call, and immediately for `look_at_board`. GPT-Live has no frame path yet (`TutorClient.sendBoardFrame` is optional).
- **Prompt.** "Every turn happens on the board": board moves by situation (new topic, explaining, asking, student answers, confused, referring, finished), pointing while talking, erasing when done, self-check from the picture. Examples A–G all include board moves. Same text feeds the GPT-Live backend and the single Gemini prompt.
- **Offline eval.** `npx tsx scripts/board-eval.ts [--model gemini-3.1-flash-lite] [--set core|math|icons|sessions|desmos|all] [--scenario fractions,system] [--turns 6] [--out file.json] [--verbose]` replays scripted student lines through a Gemini text model with the real prompt, tools and dispatcher against a fake board and prints board-use, pointing, erase and error rates per scenario. The key is on the free tier (about 5 requests a minute), so a full run takes ~15 min; the script waits out 429s. No audio, a few cents. **The default model is `gemini-3.5-flash`**, whose free tier runs out after a scenario or two; the Sept 16–17 before and after runs all used `--model gemini-3.1-flash-lite`, and runs only compare on the same model. flash-lite's daily quota covers about three sets.
- **Dev handles.** In development, `window.__chalkEditor` (tldraw Editor) and `window.__chalkBoard` (the `WhiteboardHandle`) are exposed on the session and `/dev/board` pages. `/dev/board?demo=marks` replays point/ring/erase; `?demo=rings` every kind of mark.

## Graphs: Desmos (Sept 15 2026; hardened and widened Sept 17)
Mateo found the old graphs "not good" (a fixed 300 × 220 box, numbers only at the four ends, 121 straight segments, a steep curve flattening the rest, and plain writing like "3x − 2" or "|x|" drawing "Could not read that expression" while the tool told the tutor it had graphed it). He compared Desmos, JSXGraph and Mafs side by side on the board and chose Desmos. The comparison page and the other two libraries were removed.
- **What draws.** `add_function_graph`, `plot_points` and `add_coordinate_axes` (undeclared since Sept 16 2026, still replayed) create a `graph` shape (`components/board/GraphShape.tsx`, 420 × 315 plus a 14px credit strip; three fit across a laptop board page, 480 × 360 fitted two). Its picture is an SVG made by one hidden Desmos calculator (`components/board/desmos-renderer.ts`, `asyncScreenshot` with `format: "svg"`, about 8–25 ms a graph once Desmos has loaded; the script is 4.3 MB and loads with the first graph, never on pages without one). The shape keeps the graph spec (JSON) and the SVG: crisp at any zoom, wiped in by the writing animation like typeset math. Board pictures for Gemini wait for graphs still rendering (up to 8 s), and `toSvg` renders on demand and exports the "desmos" credit with the picture.
- **Spec version 2 (Sept 17 2026).** `lib/desmos-spec.ts` (pure, unit-tested) is the spec every renderer draws from: `v: 2`, `kind`, `size`, `bounds`, the full Desmos `settings`, the expressions and tables, `markers`, and optional `sliders`, `source` and `studentState` (for Explore). It lives inside the shape's `spec` JSON because the shape has no migrations; `parseGraphSpec` reads it and upgrades a version 1 spec (size from the shape, numbered axes, rise and run turned into markers, a `source` rebuilt from its `curve1…` expressions). `source` is what the tutor asked for (`function`, `points` or `axes` with their arguments), so a graph can be redrawn without Desmos. `markers` are the words on a graph: `kind: "point"` (a dot; the dab lands on it) or `kind: "label"` with an orientation (rise and run; the dab lands on the words, `markerBox`). Before this, a highlight on "rise 4" found no marker and fell through to the only text in the shape's DOM, the credit, so it highlighted "desmos"; a graph now never measures DOM text.
- **Axis numbers and grid.** Every spec names its steps (`axisSteps`): the smallest 1, 2 or 5 × 10ⁿ step that leaves room for its widest number (about 8px a digit on x, 28px rows on y), one step for both axes when the units are square, and minor lines at least 15px apart (`minorSubdivisions`; Desmos's own choice drew them 8px apart once the steps were set). The usual −5..5 view is numbered every unit with half-unit minor lines. `autoYRange` keeps the x-axis 10% above the bottom so Desmos has room for its numbers (at 8% it pinned them, greyed, to the edge).
- **The renderer (hardened Sept 17 2026).** Every render sends every setting (a graph used to inherit the previous one's), prefixes the expression ids with a fresh `g<n>_` so no analysis from an earlier graph is read, gives up on a screenshot after 6 s and rebuilds the hidden calculator, and waits up to 400 ms for `expressionAnalysis` when none of its ids is there yet. Load status is `idle | loading | ready | failed | unavailable` (`desmosStatus`, `onDesmosStatus`); a failed load is final for the page, so later graphs and exports never wait another 20 s. `preloadDesmos()` fetches the script when the browser is idle; the session page calls it while the session connects and records `live.debug` kind `board`, `desmos_status`, on every change. The landing never preloads. A render that fails for another reason is tried once more.
- **Saved boards leave the pictures out.** `getSnapshot` blanks each graph's SVG (a board of 8 graphs saved 27 KB instead of about 230 KB) and `loadSnapshot` redraws them once the items are back: 8 graphs in 155 ms with Desmos, as vectors without it (shown at once, not written in). The in-memory copy an undone `start_new_problem` restores keeps its pictures.
- **`lib/desmos-graph.ts`** (pure, unit-tested) builds the spec. `toDesmosLatex` rewrites plain math Desmos rejects (checked against Desmos: `sqrt(x)`, `abs(x)`, `|x|`, `sin(x)`, `x²`, `e^(-x)`, `x^-2`, `pi`, the Unicode minus) into LaTeX. `graphLatexProblem` uses Compute Engine to refuse structurally broken input up front (an unclosed brace), so the dispatcher returns an error the tutor can fix in the same turn; Desmos's own per-expression errors arrive after rendering and show in `[Board: …]` as "[could not draw: …]". `graphFunction` samples curves with Compute Engine 0.128, whose `compile()` is a free function returning `{ success, run }` (older versions had `expr.compile()`). `autoYRange` trims the far 4% tails so an asymptote cannot flatten a curve; `fitBounds` squares the units only when the ranges are already within 1.5× of square (so the x range the tutor asked for survives), and a circle always gets square units with its y range derived from x. Crossings of two curves are found numerically and labelled; the slope triangle is two dashed restricted lines with "run"/"rise" labels on points of size 0.01 (a point with `pointOpacity: 0` also hides its label in Desmos's SVG); joined points are an `\operatorname{polygon}`. Labelled points keep math coordinates, so `highlight(target, text: "vertex")` dabs the point itself.
- **The tool.** `add_function_graph` accepts LaTeX or plain math and gained `y_min`, `y_max` and `extra_expressions` (shaded inequalities, circles, vertical lines, restricted pieces, up to 6, separated by ";").
- **Licence and key.** Commercial use of the Desmos API needs a Desmos partnership (partnerships@desmos.com) and its key in `NEXT_PUBLIC_DESMOS_API_KEY`. Development falls back to the public demo key from Desmos's own docs, which is for local use only. A production build without a key, or a session where Desmos fails to load, draws vector graphs instead (next bullet), so **until the partnership key is in Vercel, production shows vector graphs**.
- **Without Desmos.** `drawVectorGraph` in TldrawCore draws a graph's `source` into the same 420 × 315 box, labels included (the plot sits 28–34px inside it), so the caption and layout do not move. A graph created before a failed load is swapped in place (`swapGraphToVector`): the vector shapes take the graph's meta (item, call id), replace it in its item, and are written in again; undoing the call erases them. Curves are read by Compute Engine first (LaTeX and plain math, so `\frac{1}{x}` no longer says "Could not read"), cut at the view's edge and at asymptotes; `y_min`/`y_max` are honoured. `vectorExtra` (pure, in `desmos-graph.ts`) reads each extra expression into what vectors can draw: `y` as a function of `x` (also anything linear in `y`, like `2x+3y<6`, and a piece restricted in `x`), `x = c` (a segment when restricted in `y`), and circles (read numerically, so expanded forms work), with the shaded side of an inequality. Boundaries are dashed for strict inequalities; a shaded side is a draw shape filled in the pen with `dash: "none"` (tldraw 5 draws no outline then) at opacity 0.22, under the axes, so two sides overlap darker where both hold. Anything else is left out. Images made with Desmos tools are CC-BY-SA with attribution, hence the small "desmos" credit under each graph.
- **Pictures on Desmos (Sept 17 2026).** Mateo asked for Desmos "for many different stuff". Pure builders in `lib/` turn a tool's drawing into a spec, each with tests: `desmos-primitives.ts` (polylines as point lists with `lines: true`, polygons, dots, pixel-true arrowheads, arcs, hops, ticks, labels, `WORD` = 1.25 label size), `desmos-number-line.ts`, `desmos-bar-chart.ts` (and `chartAxes`), `desmos-figure.ts`, `desmos-data.ts` and `desmos-free.ts`. Their words are our own labels, at 1.25 times Desmos's size so they read like the board's 18px text, and every word is a marker the tutor can highlight.
  - **Number lines** (`add_number_line`): our own line, arrowheads and ticks on a picture with no grid or axes, one unit up being one pixel. Every dot's value is written in its colour, fraction ticks are stacked fractions, crowded tick labels thin out by round steps (never every third), labels that would collide take the next lane, overlapping hops arch at different heights, rays end in coloured arrowheads, a dot plot is one colour, a double number line keeps room for its unit word. `stackBase`, `reserveAbove` and `unitLabel` serve the data plots.
  - **Bar charts** (`draw_bar_chart`) and **histograms** draw their own axes, numbers, unit word and gridlines (Desmos's axes run past the plot). The vector chart (production without the switch) drew no bar for a negative value until Sept 17; `barScale` (in `board-diagrams.ts`) now reaches below zero, a negative value's number sits over the zero line, and names wider than their slot take two rows.
  - **Figures** (`draw_figure`, flat ones; solids stay vector) are drawn **to scale** when the labels give lengths: a right triangle from any two sides, a triangle from three sides or base and height, a rectangle, a square, a parallelogram, a trapezoid from its bases and height or legs, a regular pentagon or hexagon, a circle from its radius or diameter; otherwise the vector proportions, and the result says "not to scale". Numbers that cannot make the shape (6, 8 and 11 as a right triangle) come back in the result as "Careful: …" whichever renderer drew it. `grid: true` puts it on a unit grid (area by counting squares; Desmos only). When the lengths fix every angle (three sides, or a right triangle from two lengths), numeric angle labels are checked against the drawing (`angleMismatch`, within 1.5°), because a to-scale picture makes a wrong label look right: sides 7, 5, 6 with 44° at B answer "Careful: with these sides the angle at B is 57°, not 44°" (the `figures` demo had exactly that until Sept 17).
  - **`draw_data_plot`** (new tool): a dot plot and a box plot (both standing on the number line builder, so they number their own axis; box plot quartiles the grade-6 way), a histogram (bins at x = 0, 1, … like bar slots, with our own edge numbers), and a scatter plot with a linear or exponential fit computed here, so the result can state "y = 2.02x − 0.02 (r = 1)". Without Desmos a dot plot becomes a vector number line, a histogram a vector bar chart, a scatter a vector graph with its points; a box plot is refused with a suggestion.
  - **`draw_desmos`** (new tool): whatever the tutor writes for Desmos, checked item by item (`classifyDesmosLatex`: relations, bare expressions in x, points and point lists, polygons, parametric curves with a `t=0..2\pi` domain, assignments, `y~mx+b` regressions over a two-column table, histogram/dotplot/boxplot), never forced into "y = …". A letter with no value becomes a slider at 1 and the result says so; `sliders` sets values and ranges; `settings` reads 'no grid', 'square', 'x step=2', 'x label=…', 'arrows', 'degrees', 'polar', 'log y'. The view is Desmos's own square view unless an x range was given or the curves would be off it (then y fits them), or there is data (then it fits the data); circles and parametric curves count as data. Refused with a fix-it message: broken LaTeX, unknown settings, a regression without a table, an item with nothing to draw, more than 8 items.
  - **Which renderer.** `lib/desmos-config.ts`: `NEXT_PUBLIC_DESMOS_TOOLS` ("all", "none", or tool names) picks the pictures drawn on Desmos; unset, **every build draws all three on Desmos**: Mateo compared them with the vector versions on Sept 17 2026 and chose Desmos ("desmos looks good"); set it to "none" to go back. The comparison is a private artifact, "Desmos Picture Review" (https://claude.ai/code/artifact/41ea7f0b-71a0-40a9-ae1b-dd826a2493e9, Sept 17): 15 pairs and 4 Desmos-only pictures, each the board export of one call drawn alone with `desmostools=none` and `all`, with the recommendation to set `all` once the partnership key is in. - **Desmos facts (verified Sept 16 on `/dev/desmos-probe`, API v1.12, screenshot path).** The probe page renders each case to SVG and prints pass/fail; `window.__probe` holds the summary.
  - **Text in the SVG is drawn as paths.** There are no `<text>` elements; every label also gets a `<title>`, so a test that searches the SVG for label text proves nothing. Judge labels by eye.
  - **Stable output.** The same graph twice gives the same SVG once ids are ignored.
  - **Settings that show in screenshots:** `showGrid`, `showXAxis`/`showYAxis`, `xAxisStep`/`yAxisStep`, `xAxisMinorSubdivisions`, `xAxisArrowMode`, `xAxisLabel`/`yAxisLabel`, `degreeMode`, `polarMode`, `xAxisScale`. `fontSize` and `projectorMode` through `updateSettings` changed nothing (they are constructor options). `setBlank` did reset `showGrid`, but send every setting on every render anyway.
  - **Axis numbers need explicit steps.** At the board's 420×315, Desmos's automatic step numbers the x axis only every 5 units and often leaves y unnumbered (at 320×240, no numbers at all). With `xAxisStep`/`yAxisStep` set (1 on a −5..5 × −4..4 graph, 2 or 5 on wider ranges) every major line is numbered. `xAxisNumbers: false` works.
  - **Labels.** Plain text, backtick math (`` `\frac{1}{2}` `` renders stacked), `labelSize: "2"`, lowercase `labelOrientation` (`"above"` is exactly `Desmos.LabelOrientations.ABOVE`) and `${m}` interpolation all work. A label survives `pointSize: 0.01` and `hidden: true`, but **`pointOpacity: 0` hides it**.
  - **Points and lines.** `pointStyle: "OPEN"` draws a hollow point. List broadcasting works (`x=[-4,-2,0]\left\{-0.3\le y\le0.3\right\}` is many ticks in one expression). Parametric curves take `parametricDomain: {min: "0", max: "1"}`. `\operatorname{polygon}` draws with `fillOpacity`. **`segment()` is not available** ("This calculator does not support the 'segment' function"), so segments are parametric.
  - **Data.** Tables (`type: "table"`, columns `x_1`/`y_1`, `points`/`lines`) plot. `y_1\sim mx_1+b` fits, and `HelperExpression({ latex: "m" }).numericValue` reads m back. `\operatorname{histogram}(list, width)`, `\operatorname{dotplot}(list)` and `\operatorname{boxplot}(list)` draw in the SVG; the bare names fail ("Too many variables").
  - **Sliders.** `m=1` with string `sliderBounds` works, and `y=mx` follows it.
  - **Errors.** `expressionAnalysis` is empty right after `setExpressions` but correct after the screenshot, and an id reused after an error reads fresh, so reading errors after the screenshot is enough.
  - **Hangs.** A calculator whose host is not in the document still screenshots (no hang seen); keep a timeout anyway.
  - **`secret: true`** keeps an expression out of a visible calculator's list, which the Explore panel can use to hide scaffolding.
  - **Console noise.** Desmos logs "Attempted to apply path command to node g" on screenshots; it is harmless.
  - **Axis numbers need a tall picture (Sept 17).** Desmos draws no axis numbers in a screenshot under about 260px tall (250 has none, 260 has them), whatever its width or the calculator's own size; number lines, dot and box plots, bar charts and histograms therefore write their own. Numbers pinned against the picture's edge turn grey, so a data view keeps 34px under its x-axis and 40px beside its y-axis.
  - **Text size.** The calculator's `fontSize` option changes nothing in screenshots; a label's `labelSize` does (decimals like "1.25" work), and stacked fractions scale with it.
  - **Label geometry (measured Sept 17 on the board's 420 × 315 picture).** Labels are about 6.8px a character and 17px tall ("rise 4" is 37 × 17), set about 6px from their point on the side `labelOrientation` names; with the default orientation Desmos picks a side itself (left, right, above or below, whichever is free). In the SVG each label is a `g.dcg-svg-label`; its `<title>` sits on the point's own group.

## Whiteboard layout (Sept 14 2026; sections and pages Sept 16)
Mateo found the tutor used the board "like a list" (everything stacked in one or two fixed columns) and kept it in the middle. The fixed-column layout is still how tools draw, but the result is moved:
- **Pages.** The board is a page the size of the visible board, captured on the first placement after `start_new_problem` (`pageFrame`, clamped to 900–1800 × 560–1100). Pages sit side by side (`PAGE_GAP`); a new one opens only when nothing fits (next bullets). `PAGE_INSET` keeps work clear of the session chip, the End button and the watermark; `DOCK_BLOCK` (384 × 282) keeps it out from under the voice dock. The frame, the current section's region and its row top are saved in `WhiteboardSnapshot.pageState` (older snapshots with only `sectionTop` still load).
- **Placement.** `endItem` measures what a tool call drew (`itemBounds`) and nudges it into free space found by `findSpot` in `lib/board-layout.ts` (pure, unit-tested): down the first column, then the next, never overlapping, reusing erased space. Defaults per tool: an equation goes under the previous equation of the same section, a picture goes beside the words just before it, graphs and axes go to the right half. The tutor can say where with a `place` argument on every drawing tool (`parsePlace`): "beside b3", "below b3", or any area the summary names (`AREA_NAMES`: the halves "left", "right", "top", "bottom"; "the left third", "the middle band" and the other thirds and bands; the nine cells "top left" … "centre" … "bottom right"; `areaFromWords` also reads "in the top-right corner", "center", "lower left"). A named place is looked for on the whole page, wholly inside the area if it fits, else centred in it, else nearest. The old `column` argument still works as left/right. Default work fills the current section's region, then spills onto the rest of the page, and only then opens a page. Headings place themselves and own their row: the problem heading the page's, a section heading its region's. Each item's placed rectangle is cached (`placedRectsRef`) because a reveal in progress changes live bounds.
- **Sections and pages (Sept 16 2026).** A recorded session (`session_1789536065273_3ncyif`) ran to four pages, about 4,800px wide, and at one point 8 of the 9 items the tutor referred to were on pages the student could not see.   - `planSection` (pure, in `lib/board-layout.ts`) fills a page the way text fills one: a panel beside the current row of sections while there is width, else a band under all the work (a new row), else a panel under the right-hand work, else null (a new page). A region needs a clear 420 × 240 block (heading included) away from the dock. Section headings count as their words when planning, so the next section can sit beside them.
  - A section's first item that does not fit under its heading takes the heading with it (`rehomeSection` in the handle): to room on this page that holds both, else to a fresh page. A heading never sits apart from its work.
  - `place: "new page"` is honoured only at a section start on a mostly used page (`shouldOpenPage`: 6 of the 8 usable cells hold work, headings counted by their words, `usedCellsOn`), and the heading moves along; otherwise the result says "stayed on this page: there was room". "New page" is no longer in the tool description.
  - Tool results carry notes from `takeNotes()`: that, "b2 is on page 1, so the board turns there to show it" for a mark on another page, and `no room at "bottom left", so it is at the top middle`.
  - `focusOn` frames the page that holds the item (so pointing back turns the board to page 1), and on a phone an item in a right-hand panel is framed on its own instead of from the page's left edge.
  - Replay of that session's 68 calls at its 1454 × 818 board: before, 3 pages and 3,948px wide, with every listed item off-page after each section; after, 2 pages, both "new page" requests stayed, and the graph section moved to page 2 with its graph instead of leaving the graph under a callout.

## Onboarding (Sept 20 2026)
Mateo asked for the five-step onboarding to be scrapped ("a first, ever version") and rebuilt as the first step toward a tutor personalised to each student, with separate paths for parents and students. The research behind the design is the "Knowing the Student" artifact (https://claude.ai/code/artifact/19c52738-11e8-499d-b4fd-af8e1fdc7a75): self-report predicts ability at about r = .29, a fifth to nearly half of teenagers straightline rating scales, and Aristotle's nine-question onboarding collects no ability data either. So the flow asks only what cannot be observed, and the tutor learns the rest by teaching.
- **The flow** (`app/onboarding/page.tsx`, in the sign-in page's frame: a narrow column beside the swirl panel, so signing up and setting up read as one thing). First screen: student or parent. ## GPT-Live protocol facts we verified (do not relearn these)
1. The Live model's clock is driven by **inbound audio**. With no mic track nothing happens: appended context is never injected and the model never speaks. Text-only QA sessions send faint synthetic room tone (`createSyntheticMicStream`).
2. `session.instructions.append` alone never makes the model speak. `session.commentary.append` does (a near-verbatim paraphrase within ~1 s). The greeting and the resume line are sent as commentary.
3. Client-triggered backend turns work: `response.item.create` (user message or attachments) + `response.create` → the Live service creates a delegation, the voice model bridges ("let me put that on the board"), then speaks the backend's text. Typed messages and file uploads use this path.
4. Tool loop: nested `response.output_item.done` (`function_call`) → execute on the board → `response.item.create {function_call_output}` → after the nested `response.completed`, send exactly one `response.create`.
5. Sessions expire after about 2 hours (`expires_at` in `session.started`). Voice and voice instructions are immutable per session; backend settings can change with `session.update`.
6. The voice model cannot see images. Photos and PDFs go to the backend as `input_image` / `input_file` items.
7. The SDK (`openai@7.15`) has typed Live events in `node_modules/openai/resources/live/live.d.ts` and a WebSocket client (`openai/resources/live/ws`) that is handy for Node probes.

- **Which Live model (Sept 17 2026).** `LIVE_MODELS` in `lib/gemini-live.ts`: `3.1` = `gemini-3.1-flash-live-preview` (still the default), `3.8` = `gemini-3.8-live`, `3.8-thinking` = `gemini-3.8-live-extended-thinking`. `resolveLiveModel` picks one: `?live=3.8` on a session URL for one tab, else `NEXT_PUBLIC_GEMINI_LIVE_MODEL`, else the default; a full model id passes through, so a model released later needs no code change. The session chip shows which ran ("gemini 3.8") and `session.started` records it.
  - **What the API says.** Google now calls 3.1 a "legacy audio-to-audio preview model. We recommend updating to Gemini 3.8 Live"; `gemini-3.8-live` is stable and "the default for most low-latency voice agent experiences", `gemini-3.8-live-extended-thinking` stable and "recommended when higher background reasoning is required". Both are 131k in / 65k out.
  - **What 3.8 adds, and what held up here (Sept 17 2026).** Google's announcement lists asynchronous function calling, visual grounding, alphanumeric precision, 97+ languages and incremental content updates, at $0.005 a minute of audio in and $0.018 out (a 30-minute session lands near $0.40, against $1.60–2.10 on GPT-Live). Tested on our own stack with `scripts/live-model-probe.ts`:
    - **Async tools did nothing for us.** `behavior: "NON_BLOCKING"` on every declaration plus `scheduling` on the responses is accepted, but with an 8 s board the model still said nothing until the results arrived, on v1alpha and v1beta alike. No dead-air win; revisit on a later model.
    - **`enableAffectiveDialog` does not exist in the API.** Rejected at `setup` and inside `generationConfig`, on both versions ("Cannot find field"), though the guide lists it.
    - **`proactivity.proactiveAudio` and `mediaResolution` are accepted** on our v1alpha endpoint, but 3.1 accepts them too, so acceptance proves nothing. `MEDIA_RESOLUTION_HIGH` made board reading no better and pushed first audio from 4.1 s to 8.5 s.
    - **Board reading is not visibly better.** Asked to read a real board export (heading, a substituted slope formula, a graph with a rise-over-run triangle, a student attempt, a number line), 3.1 and 3.8 both read it back correctly.
    - **No thought summaries.** Still nothing with `includeThoughts`, so the replay cannot show reasoning.
  - **What our own probe found** (`scripts/live-model-probe.ts`, one student line, the real prompt and all 40 tool declarations): `gemini-3.8-live` works, calls its tools one at a time instead of in a single batch, draws before it speaks (first audio 2.9–5.3 s against 3.1's 1.9 s) and finishes the turn sooner (10–12 s against 15 s). `gemini-3.8-live-extended-thinking` closes the socket with 1007 unless `thinkingConfig.thinkingLevel` is set, then answers "I'm sorry, a system error occurred" on v1beta whether or not our tools and prompt are attached, and on v1alpha (the endpoint the browser uses) sits silent for about 22 s before drawing: not usable for a live tutor. No model returned thought parts, `includeThoughts` or not.
- Gemini has no Responses-delegation split, so the whiteboard tools are called by the voice model directly. Expect it to draw less carefully than the OpenAI pair.

## Learning evidence and shared tutoring runtime (Sept 17 2026)
- **One pedagogical owner.** `TutorRuntime` in `lib/tutor-runtime.ts` owns the `TutorPolicy`, current assistance ledger, tutor-tool execution, cancellation, and typed learning events. `LiveTutorSession` and `GeminiLiveSession` receive the same runtime from `app/session/[id]/page.tsx`; they are transports for audio, transcript, and tool messages, not separate teaching brains. Reconnects and provider replacement therefore keep the current skill, attempts, signals, and help history.
- **Canonical skills.** `lib/skill-catalog.ts` is the small, stable catalog for math the deterministic checker can judge. Resolution is exact over a key, label, or explicit alias. Always store `rawSkill`; an unknown label stays unresolved instead of creating a permanent skill. Add a catalog alias only when it is unambiguous, and keep the SQL seed in `lib/db/sql/2026-09-17-learning-evidence.sql` synchronized.
- **Assistance is evidence.** The model calls `record_teaching_move` before H1-H5 help and for deliberate H0 independent checks. Observable moves have minimum levels enforced in code: focusing question H1, point H2, strategy hint/counterexample H3, shown step H4, worked example H5, independent check H0. The runtime and server both use the maximum of the declared level and observable moves. Alias differences such as “solving two step equations” and “two-step equations” share one ledger. Missing help falls back to at least H1, never H0.
- **Attempts are immutable facts.** `check_answer` remains synchronous for the live loop. The runtime emits the problem, answer, raw/canonical skill, checker result, effective help, call id, and a stable problem fingerprint. `LearningRecorder` in `lib/learning-client.ts` batches and retries these events outside the voice path. A cancelled call is marked cancelled and reprojected; its audit row is not deleted.
- **Server trust boundary.** `/api/sessions/[id]/learning` verifies auth and session ownership. `lib/db/learning.ts` resolves the canonical skill, recomputes the math verdict and fingerprint, enforces move minimums, looks up assistance since the preceding attempt, inserts idempotently, and reprojects affected skills. Do not accept a browser-supplied verdict, canonical key, or H0 claim as authoritative.
- **Storage.** Apply `lib/db/sql/2026-09-17-learning-evidence.sql` once in Neon. It creates/seeds `skills`, `teaching_moves`, `learning_attempts`, and `learner_skill_states`. The prompt overview deliberately falls back to empty when the migration or database is unavailable, so evidence is shadow-first and a storage outage does not block tutoring.
- **Projection rules.** Pure rules live in `lib/learning-evidence.ts`: `building` has attempts but no success; `supported` is a correct H1-H5 answer; `independent_recent` is a recent correct H0 answer; `review_due` is independent evidence at least 24 hours old; `retained` needs correct H0 work on distinct problems at least 24 hours apart; `needs_revisit` is a substantive miss after success. `unchecked` and cancelled work do not count. A slip alone does not erase retention.
- **Consumers.** `lib/learning-overview.ts` reads projections and refreshes time-based `review_due`; `/api/learning/overview` serves it. Both live-session routes append its three-item learner brief to the teaching prompt. The brief is a soft guide: the student's explicit goal wins, and at most one relevant warm-up is offered. `HomePage` reads the same overview; there are no fabricated focus rows or mastery claims.
- **Closing behavior.** An independent exit check is offered, not forced. If the student declines or needs to leave, the tutor closes warmly. Do not restore the old “Never end on I don't know” rule.
- **Tests.** The catalog, projection, runtime, server validation, retry queue, overview, prompt contract, provider sharing, and home view model all have focused unit tests. `npm test` was 251/251 after this addition. Full `npm run lint` still reports the five documented pre-existing errors in `Magnet`, animate-ui tabs/highlight, and `dot-pattern`; lint all touched files directly when checking this feature.

- Neither live API has a speaking-rate setting: Gemini's `speechConfig` is voice and language only, GPT-Live has none (only the older Realtime API had `speed`). If the worklet cannot load, or throws later (`processorerror`), playback falls back to plain buffers at 1×.
- The pill shows only on Gemini sessions (`TutorClient.setSpeechRate` is optional). GPT-Live's voice arrives as a live WebRTC track; slowing that would pile up delay.
- **The library is vendored, not bundled.** `npm run vendor:stretch` (`scripts/vendor-stretch.mjs`) copies it from the devDependency into `public/vendor/signalsmith-stretch.mjs`, and `lib/audio.ts` imports that URL with a `webpackIgnore` comment (`/vendor` is a static path in `proxy.ts`). Bundled by Turbopack, the worklet never became ready (4 s timeout); the same file unbundled was ready in about 10 ms. The script also **patches a streaming bug in 1.3.2**: the worklet's buffer copy loop drifts across many small appended buffers and throws, so 40 ms chunks (what Gemini sends) killed the node within about 150 ms, silently. The script fails if those lines change; re-check the patch before upgrading, then bump `?v=` in `STRETCH_URL`.
- **Free audio QA:** `/dev/voice` (dev only) streams a speech sample into the real `AudioPlayer` in 40 ms chunks at twice real time, the way Gemini delivers a turn, and reports heard duration against expected, the engine mode, and interrupts; `window.__voiceLab` has `play`, `interrupt`, `setRate`, `stats()`, `debug()`. The sample is local only (`public/dev/` is gitignored): make it with the `say` and `afconvert` lines at the top of `app/dev/voice/VoiceLab.tsx`. Close the lab's player on Fast Refresh (it does); a closed context streams silence.
- Engine check on `/dev/voice` (Sept 14, 8.5 s sample, before the stops were named): heard 8.48 s at 1× (8.52 expected), 9.40 s at 0.9× (9.46), 10.58 s at 0.8× (10.65), 7.08 s at 1.2× (7.10); a switch from 1× to 0.8× mid-sentence 9.80 s (9.84); an interrupt silent within 400 ms; the next play after it complete. Speech starts about 120 ms later than before (the engine's latency). Not yet tried in a real Gemini session or a production build.

## Gotchas
- Branch order: `gpt-live` > `v2` > `main`. Never base work on `main`.
- Background agents must not run `git checkout` / `switch` / `stash`; one did during a read-only audit and moved the working tree to `main`.
- `.playwright-mcp/` is gitignored; Playwright MCP writes screenshots and snapshots there.
- Turbopack sometimes keeps serving a stale `globals.css` after an edit (the class you just added is missing from the served stylesheet). Fix: stop the dev server, `rm -rf .next`, start it again.
- Never give every element a transition, not even a tiny one. `transition-property` defaults to `all`, so the old reduced-motion reset in `globals.css` (`transition-duration: 0.01ms !important` on `*`) turned every style change into a transition, and tldraw, which measures text by restyling one hidden element and reading its size at once, got the previous size back. Under reduced motion every board note measured one line tall and the board overlapped; normal motion hid it because the typing animation measures the text again later (found Sept 16 2026; the reset now sets `0s`).
- tldraw colours are registered globally by whichever editor mounts, and `registerColorsFromThemes` also removes colours missing from its themes. Every board must mount with `BOARD_THEMES` (today `TldrawCore` is the only mount), or shapes in `sky`, `sky-deep` or `pencil` fail validation.
- Every tool call blocks Gemini 3.1 Flash Live until its response arrives, so a tool handler must answer fast (the client caps it at 3 s). A picture the tutor should see with the answer (`look_at_board`, `look_at_worksheet`) is sent before the response, never after, and at most about once a second.
- The Playwright MCP browser window is shared: other things can click in it mid-check (on Sept 16 a demo nav link was clicked during a run and the numbers came from the wrong demo). For board checks whose numbers matter, drive a private headless Chrome with `puppeteer-core` (already a dependency, as `scripts/landing-shots.mjs` does) and confirm each result matches the calls you sent.
