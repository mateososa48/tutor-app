# tutor-app — notes for agents and future sessions

## This is NOT the Next.js you know
This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` before writing any code. Heed deprecation notices.

## What this is
A live voice tutor for students in grades 5–12 with a shared whiteboard. The student talks; the tutor talks back and writes on a tldraw canvas as it teaches. Brand working name: Chalk. `PRODUCT.md` is the design brief.

## Stack
- Next.js 16 App Router, React 19, TypeScript, Tailwind v4 (CSS-first, tokens in `app/globals.css`).
- Voice: **OpenAI GPT-Live-1** over WebRTC (`gpt-live-1`). Teaching brain: a Responses model via GPT-Live "Responses delegation" (`gpt-5.6-terra` by default).
- Voice fallback: **Gemini Live** (`gemini-3.1-flash-live-preview`, one model talks and draws) behind the same client surface; picked per session, see "Voice provider switch".
- Board: tldraw v5 + KaTeX (`components/TldrawCore.tsx`, `lib/semantic-board.ts`).
- Auth: next-auth v5 (JWT). DB: Neon Postgres via Drizzle (`lib/db/schema.ts`). Route protection in `proxy.ts`.

## Architecture (branch `gpt-live`, Sept 2026)
- `app/api/live-session/route.ts` — POST with the browser's SDP offer. Loads the student's profile and memory notes, composes both prompts, registers the whiteboard tools with the backend, calls `client.live.create`, returns the SDP answer plus the greeting/resume lines. The OpenAI key never leaves the server.
- `lib/live-tutor.ts` — browser client: mic track + `oai-events` data channel, transcript assembly, backend tool loop, speaking meter (RMS on the remote track), reconnect-with-history on drop.
- `lib/live-events.ts` — pure reducers (`TranscriptAssembler`, `BackendTurnTracker`), unit-tested.
- `lib/tutor-prompts.ts` — the prompts, built from named sections. Voice model: persona, speaking style, backchannel, interruption, delegation, boundaries. Backend: output contract, then the teaching sections (see "How the tutor teaches"), the whiteboard section, the student profile and memory, files/safety/reconnect, and eight teaching-moment examples. Gemini gets the conversation sections minus delegation, plus the same teaching sections.
- `lib/whiteboard-tools.ts` — the tool declarations (single source of truth) and `WHITEBOARD_FUNCTION_TOOLS` (Responses format). `lib/whiteboard-tool-dispatch.ts` validates arguments, calls the board handle, and returns a result that describes the picture ("Drew 1 circle cut into 2 equal parts, 1 shaded"); the session page appends a `[Board: …]` summary so the backend knows what the student sees.
- `lib/board-diagrams.ts` — pure, unit-tested math and parsers behind the picture tools (fractions, tick steps and fraction labels, intervals/jumps syntax, figure vertices and label placement, sketch strokes). `components/TldrawCore.tsx` turns the parsed inputs into tldraw shapes.

- `app/api/profile/notes/route.ts` — durable tutor memory (`user_profiles.tutor_notes`), written by the `remember_about_student` tool and loaded into the backend prompt at session start.
- Voice previews are gone (Sept 14): the old `app/api/voice-preview` route played OpenAI TTS, which failed once the account ran out of credits and never matched the Gemini voice a session actually uses.
- `app/session/[id]/page.tsx` — session orchestration and persistence (transcript events, board snapshots, heartbeat, pause/resume).

## How the tutor teaches (Sept 15 2026)
- The prompt follows the tutoring research in the "How Chalk Should Teach" review (expert tutors, Bridge, Tutor CoPilot, worked examples and fading, feedback research). Teaching comes before the board in the prompt: "What you are for", "How every turn works" (classify the move, decide what they need, end with something for the student to do), "Reading the student's answer" (correct/unsure/slip/wrong idea/partial/guess, and never call a wrong answer right), "How much help" (levels H0 wait → H5 worked example then fade; novices start high, students who are getting it start low), "Feedback and praise" (praise the move, flag mistakes indirectly), "Adapting up and down" (feelings first, confusion is not an emergency, raise the challenge when they cruise), "The session" (warm-up from notes, reflection after a solve, closing check and "Today's rule"), "When they want the answer" (a worked parallel problem as the fair fast path).
- Removed on purpose: "EVERY reply includes at least one board action", "start as high on the hint ladder as you can", immediate cross-outs of wrong answers, and repeated example openers ("Totally fair"). Onboarding slider preferences now appear only as "Stated preferences (a soft default; trust what you see them do over this)", and only when set.
- Gemini used to lose the backchannel, interruption, and boundaries rules (the persona was sliced at "# Backchannel policy"). Fixed; a unit test guards it.
- **Tutor tools and policy (Sept 15 2026).** Two app-owned tools live in `lib/tutor-tools.ts`, declared apart from the whiteboard tools and added next to them in `gemini-live.ts` (setup), `app/api/live-session/route.ts` (Responses tools) and `scripts/tutor-eval.ts`. `check_answer(problem, student_answer)` runs `lib/answer-check.ts`, a deterministic checker on `math-expression.ts`: arithmetic, fractions, percent and "of", mixed numbers, simple LaTeX, implicit multiplication, one letter renamed to x, linear and quadratic equations (it knows the solutions, so "3" for x² = 9 is `partial`), and expression equivalence by sampling. It returns correct / partial / incorrect / cannot_check, never guesses on ambiguous input ("3 4", two letters, inequalities), and may give the right value "for you only". `record_attempt(skill, result, help_level, note?)` feeds `lib/tutor-policy.ts`.
- The policy (pure, unit-tested, one instance per live client; replaces the old `tutor-state.ts`) keeps attempts, misses in a row, quick-right streaks, and signals read from whole student utterances (frustrated, confused, idk, bored, unsure; each counts for two utterances). It builds one line: `[Tutor state: skill "adding fractions": 0 of 2 right · 2 misses in a row (last: stuck) · suggested help H3 (2 misses in a row) · down: sounds frustrated (…) · 9 min in. Not from the student; never read it aloud.]`. Tutor tools always answer with it; board tool results carry it only when it changed (`takeStateUpdate`). Nothing is injected as an extra model turn any more (the old Gemini downshift made the tutor speak again after its turn). Gemini collects input-transcript fragments and reads the utterance once the tutor answers or calls a tool; GPT-Live reads flushed student utterances and typed text. Attempts are session-only for now.
- The prompt says: call check_answer before calling an answer right or wrong, then record_attempt, and follow the suggested help level unless what you see says otherwise; the examples show both tools. `lib/tutor-tools.test.ts` fails if a prompt example names a tool that is not declared.
- Still not built (planned in the review): a learner model that persists skills and session summaries across sessions, a student pen on the board, Gemini VAD/thinking tuning, onboarding changes.
- **Teaching eval.** `npx tsx scripts/tutor-eval.ts [--persona misconception,anxious] [--turns 6] [--tutor gemini-3.5-flash] [--student gemini-3.5-flash-lite] [--judge gemini-3.8-flash] [--out file.json] [--verbose] [--prompt path]`. `--prompt` loads another copy of `tutor-prompts.ts` (for example `git show HEAD:lib/tutor-prompts.ts > /tmp/old/tutor-prompts.ts`) so two prompt versions can be compared on the same students. Seven simulated students (misconception, careless, answer-seeker, anxious, bored-advanced, novice, idk) talk to the real Gemini prompt, tools, and dispatcher on a fake board; a judge grades every tutor turn: mistakes caught, wrong answers confirmed, answer leaked, targeted remediation, ends with a student action, generic praise, help-level fit, 2+ questions, words per turn, board use, and whether the persona's success condition was met. The key is on the free tier: gemini-3.1-pro has no quota (limit 0), and flash models allow 20 requests per day per model, while one persona uses about 15 tutor calls. So on the free tier the eval runs roughly one persona a day; an old-vs-new comparison needs billing on the key. The script fails fast on both quota errors instead of waiting. Simulated students are too agreeable (they drop wrong ideas easily), so treat the numbers as a comparison between prompt versions, not a measure of real learning.

## The board (Sept 2026 rebuild)
- Picture tools, all rendered from real tldraw shapes: `draw_fraction` (pie or bar, improper fractions get extra wholes, typeset "= 3/4" beside the model), `add_number_line` (step, fraction tick labels, dots, shaded intervals with open/closed ends and rays, hop arrows), `draw_figure` (triangle, right triangle, square, rectangle, circle with side/vertex/angle/radius/diameter labels), `draw_angle`, `draw_array` (with dashed group splits), `add_area_model`, `draw_balance` (equation as a scale), `draw_bar_chart`, `draw_sketch` (polylines in a 0–100 box, the escape hatch). `add_function_graph`, `add_coordinate_axes`, `plot_points` draw vector axes with arrowheads and ticks; nothing is a PNG any more.
- Style rules in `TldrawCore.tsx`: `INK` (black) for structure, `PENCIL` (grey) for the student's attempts and captions, and a marker palette (`MARKERS`: blue, violet, green, orange, red, light blue) for the tutor's drawings. `takePens(n)` hands each new diagram, and each series inside one, the next pen, so two fractions, five bars or three forces never share a colour; the counter resets on `start_new_problem`. Highlights are green, cross-outs red. Headings are sans; notes and student work are tldraw's handwriting face; diagram labels are sans. Box heights come from `measureText` (tldraw's own text measurer), never from character counts. Diagrams use solid strokes; only `draw_sketch` keeps the hand-drawn wobble.
- Typeset math is a real tldraw shape: `components/board/MathShape.tsx` (`type: "math"`, registered through `TLGlobalShapePropsMap`) renders KaTeX in an `HTMLContainer`, measures itself off-screen at creation (`measureMath`), and carries `annotation`, `crossOut`, `highlight`, `reveal` (the writing animation) and `role` (`"label"` for the "= 3/4" captions beside fraction models, which `highlight_step` / `cross_out_step` skip). `toSvg` exports the line as plain text (`lib/latex-plain.ts`) with its cross-out and ring, so board pictures need no compositing. That export is what the tutor and the admin replay see, so a bug there blinds the tutor to its own board while the student sees correct KaTeX: until Sept 15 `\pm` matched the front of `\pmod` ("±od6"), `\equiv`/`\mid`/`\nmid` were stripped as unknown commands, and `\_` printed its backslash. `latex-plain.test.ts` now covers the cases real sessions produced. `createMath` in TldrawCore creates them; `mathOrderRef` keeps creation order for "newest line" lookups. Old snapshots with `eqItems` overlay records are turned into shapes on load. `.chalk-math .katex-display { margin: 0 }` keeps the box tight.
- Camera: `focusOn` treats "visible but zoomed out below 0.8" as not visible, so new content always comes back to a readable zoom (this is why the first drawing looked tiny when the student had zoomed out). Since the Sept 14 layout work it frames the whole board page when the page fits on screen at that zoom, so the board holds still while the tutor writes, and otherwise (phones) it frames the item's row from the page's left edge, so a row never loses its start off screen. On a 390px phone that lands around 0.55 zoom; the 0.8 clamp after an animated `zoomToBounds` reads the pre-animation zoom and does not fire (older quirk, left as is). It is a no-op while a tool call is still drawing; `endItem` focuses once the drawing is placed.
- Backend prompt (`lib/tutor-prompts.ts`) has a board-first rule: one diagnostic question at most, then draw the picture in the same reply as the idea; never describe a picture in words or fake one with brackets; one to three board actions per reply. Examples B, B2, B3 show fractions, a sketch and the balance.
- **Board use, fixed Sept 15 2026** after measuring every recorded session (55 tool calls). What was wrong: two sessions had ZERO tool calls while the tutor said "Focus on the table on the board" and "On the board, I've drawn a triangle" (students answered about a blank board); 24 of 41 shipped tools had never been called once, `draw_figure` and `draw_sketch` among them; text containers were 47% of all calls against 20% real pictures. The tools were registered the whole time, so this was the model taking the cheap path, not a regression. Evidence and numbers: `project_board_use.md` in memory.
  - The board section now opens with **three rules that override the rest**: (1) the first reply on a new topic calls `start_new_problem` and draws it in the same reply, and a topic with no picture tool is still drawn (`draw_sketch`, `draw_figure`, `add_table`, `add_number_line`); (2) never mention board content that was not drawn; (3) words on the board are labels, not explanations. The ceiling in `tutor-prompts.test.ts` moved 19000 -> 19200 to pay for them (268 chars net after trimming the lines they replaced). Raise it again only for a rule that earns it.
  - **The caps are enforced in the dispatcher, not just described**: `add_text_note` 160 chars, `add_worked_example_box` 140 chars over at most 3 lines (`NOTE_MAX` / `BOX_BODY_MAX` / `BOX_BODY_LINES` in `lib/whiteboard-tool-dispatch.ts`). Over the cap the call is refused with the instruction ("say the explanation out loud, or draw the idea instead"), because the model ignores tool descriptions but reacts to tool errors.
  - `draw_sketch` is now the declared **fallback** for any topic without a picture tool, instead of a tool whose own description told the model to prefer others.
  - `sendInitialGreeting`'s "Do not start teaching until the task is identified" now carries the counterpart "the moment they name it, your first reply about it puts it on the board", and the resume instruction no longer says "do not use whiteboard tools until a concrete task is confirmed" (it kept the anti-hallucination half).
  - `scripts/board-eval.ts` scores two new things: **picture rate** (a real diagram, not another box of words) and **phantom board claims** (the tutor saying "on the board" when nothing was drawn that turn). Run it before and after any prompt change here.
- **Free visual QA:** `npm run dev` then open `/dev/board?demo=fractions|algebra|geometry|data|all&step=300&count=N`. It mounts the whiteboard and replays scripted tool calls with no OpenAI session (`app/dev/board/demos.ts`). The route is dev-only (404 in production, public in `proxy.ts` only in development). Screenshot it before touching a renderer.

## Math only (Sept 14 2026)
Chalk tutors math and nothing else (arithmetic, fractions, decimals, percent, ratios, negatives, algebra, geometry, graphs, basic statistics). The prompts say so in the persona, a "# Math only" section, and the Gemini contract; the landing FAQ, onboarding examples, and debug panel match. The board section carries a topic playbook: which picture tool for which topic. Picture tools added for the math focus, all in `components/TldrawCore.tsx` with pure helpers in `lib/board-diagrams.ts`:
- `draw_tape_diagram` (bar model: rows of boxes, `*` shades a box, `= total`, a bracket for the grand total) for ratios, parts and totals, a fraction of an amount.
- `draw_grid` (rows × columns, first N shaded) for percent, decimals, fraction of a set, area as counting squares.
- `write_vertical` (stacked +, −, × with carries and partial products, right-aligned mono) and `draw_long_division` (bracket, quotient, step lines; leading spaces place digits).
- `draw_transversal` (two parallels and a transversal, angles 1–8 clockwise from upper left, `mark_angles` arcs).
- `draw_figure` grew parallelogram, trapezoid, rhombus, pentagon, hexagon, and 3D rectangular_prism / cube / cylinder (`side_labels` = dimensions), plus `height_label` (dashed altitude with a right-angle mark). Side labels are positional: "12 | | 6" skips the right side.
- `add_function_graph` grew `mark_points`, `slope_run` (a rise/run triangle), and `second_expression` (two curves, crossing point marked: systems of equations); `draw_array` grew `shaded`; `draw_angle` grew `adjacent_degrees` (angles on a line / around a point); `add_number_line` grew `label_style` (tenths read as decimals by default) and `second_min`/`second_max` (a double number line for percent of an amount); `plot_points` grew `connect` (join into a polygon).
- `draw_fraction` grew `common_denominator` (1/2 and 1/3 recut into sixths); `draw_grid` grew `shade_rows`/`shade_columns` (rows tinted, columns tinted, overlap in full colour: multiplying fractions); repeated number-line points stack into a dot plot. Note, callout, setup, and table results quote their content so the tutor can point at or erase them by what they say.
- **Real things** (Sept 14 2026): `draw_icons` puts rows of everyday objects on the board (apples, cookies, coins, cars, animals, balloons…) with `group_size` gaps, `crossed` red X's, and a `second_icon` row, for counting, sharing, taking away, ratios, and everyday analogies. Icons are Fluent Emoji Flat (Microsoft, MIT) from `@iconify-json/fluent-emoji-flat` (devDependency): `scripts/build-icons.ts` curates the list (118 names) into `lib/board-icons.generated.ts` (SVG bodies, client only) and `lib/board-icon-names.generated.ts` (names, shared with the tool declaration's enum). `components/board/IconShape.tsx` is the `icon` shape (inline SVG, exports itself, reveal pops in). Re-run the script after editing the list. The MIT notice lives in the generated file header.
- LaTeX from the model goes through `lib/latex-normalize.ts` in the dispatcher (unicode operators and superscripts, vulgar fractions, degrees, bare `%`, words wrapped in `\text{}` with their spaces, units upright, lone `a/b` as fractions, `\\` line breaks split into separate lines except inside environments). `renderMathHtml` tries the LaTeX as written, then normalised, then as plain text; KaTeX error markup never reaches the board. Equation rows are pitched by measured height (`max(EQ_H, h + 6)`).
- Icon names resolve loosely (`lib/board-icons.ts`: plurals, phrases, aliases like kids/money/ice cream). Erasing an item leaves its space free for the next drawing; nothing slides up (the column reflow was removed with the Sept 14 layout work). Board items are saved in `WhiteboardSnapshot.items` and rebuilt from `meta.itemId` for older snapshots, so resumed sessions keep their ids.
- `/dev/board?demo=math`, `?demo=icons`, `?demo=icons2` (layout edge cases), and `?demo=eqs` (LaTeX torture: unicode, tall lines, bad input, marks, erase, cases) replay all of it. `/dev/board?script=<URL-encoded JSON [{name,args}]>` replays arbitrary calls; the eval logs' `↳ tool({args})` lines can be lifted straight into it to see the board a model actually built.
- `highlight_step` / `cross_out_step` fall back from equation lines to any item by label (green ring/underline/box, red strike), because models mark the student's attempt with them. Student attempts are labelled by their text. Item bounds read the full text of a line still being written (`revealTextRef`).
- Eval on the 12-topic math set, before → after the math work (gemini-3.1-flash-lite): board use 97% → 96%, pointing 28% → 35%, sketch-or-text fallbacks 12 → 9 turns; the after run's tool errors were all target-matching cases fixed since (token matching, newest-line default, caption-preserving labels). Equation-line labels are plain text (`lib/latex-plain.ts`) so `point_at "5/6"` resolves. The eval has a `--set math` scenario set (12 topics).

## The tutor's hands (Sept 14 2026)
- **Board items.** Every tool call is one item with a short id (`b1`, `b2`, …). `dispatchWhiteboardTool` wraps each call in `board.beginItem/endItem`; the id rides in the result ("… (item b7)") and `getBoardSummary()` returns the item list (`formatBoardItems` in `lib/board-items.ts`) that the page appends as `[Board: …]`. Items resolve by id, label words, kind, or `last` (`resolveItemTarget`, unit-tested). Item bounds measure rendered text and typeset math, not their wide layout boxes.
- **Pointer and rings.** The tutor is a tldraw collaborator: an `instance_presence` record (`userId: "tutor"`, sky blue) drawn by `components/board/TutorPenOverlay.ts` (replaces tldraw's collaborator cursor overlay with a pen glyph and a name tag). `point_at` glides it onto an item with a small tap; `circle_item` draws a laser ring (presence `scribbles`, fades after ~3 s) or, with `keep=true`, an orange marker stroke. `erase_items` / `erase_older` delete items (shapes + typeset lines). The cursor hides after ~6 s idle.
- **Highlighter** (Sept 14 2026). `highlight(target, text?, color)` runs a real tldraw `highlight` stroke (drawn behind the ink) over the exact words in an item, e.g. `text="2x"` in an equation line or a tick label on a number line, or over the whole item. A drawing gets a slim marker ring in the same colour family instead: a highlighter ring smothered the drawing, and tldraw's highlight `scale` cannot thin it because its SVG export divides positions by the scale. Short words need care: tldraw's `getStrokePoints` drops points within a third of the stroke size of either end and skips the first three points until the stroke is a full stroke-size long, so a short, sparse swipe collapsed into a dot at its left end. Short swipes use 1px point spacing and a run of at least two thirds of the stroke size plus 4px (`swipePoints`). Colours mean something and the prompt says so: yellow look here, green right, pink the mistake, blue the step we are on (tldraw yellow, light-green, light-red, light-blue). The dispatcher checks the words synchronously (`normalizeForMatch` / `matchVariants` in `lib/board-items.ts`, which also match a typeset fraction whose DOM has no slash and puts the denominator first), so the tool result says honestly when it fell back to the whole item. The stroke is placed by measuring the words in the shape's DOM (`[data-shape-id]`, text-node ranges only so KaTeX's tall layout boxes never count, `.katex-mathml` skipped, math annotations skipped) and converting with `editor.screenToPage`; it queues behind the writing, joins the item (erased with it), and exports with board pictures. `highlight_step` is now for whole equation lines. `/dev/board?demo=highlight` replays it.
- **Written, not pasted.** `revealItem` hides everything a tool call created and a queue writes it in reading order with the cursor leading (`lib/board-reveal.ts` plans order and durations): text types out, strokes and lines grow point by point (original points kept in `strokePointsRef`), boxes and arrows fade, typeset math wipes in. The pace is an unhurried hand: about 20 characters a second, a 4.5 s cap per tool call, a pen glide and a short pause before each big piece (the Sept 14 speed was 1.8 s and read as rushed). `catchUpPace` speeds a call up only when tool calls are queued behind it. Pointing and rings queue behind the writing. `onWriting` keeps the dock badge on "Writing on the board" while the queue runs. Reduced motion skips the animation.
- **The tutor sees the board.** `exportImage()` waits for the queue, then renders the board to a JPEG (every shape exports itself; math shapes export as plain text with cross-outs and highlights). The session page sends one to Gemini as a `realtimeInput.video` frame about 1 s after each tool call, and immediately for `look_at_board`. GPT-Live has no frame path yet (`TutorClient.sendBoardFrame` is optional).
- **Prompt.** "Every turn happens on the board": board moves by situation (new topic, explaining, asking, student answers, confused, referring, finished), pointing while talking, erasing when done, self-check from the picture. Examples A–G all include board moves. Same text feeds the GPT-Live backend and the single Gemini prompt.
- **Offline eval.** `npx tsx scripts/board-eval.ts [--model gemini-3.1-flash-lite] [--scenario fractions] [--turns 6] [--verbose]` replays scripted student lines through a Gemini text model with the real prompt, tools and dispatcher against a fake board and prints board-use, pointing, erase and error rates per scenario. The key is on the free tier (about 5 requests a minute), so a full run takes ~15 min; the script waits out 429s. No audio, a few cents.
- **Dev handles.** In development, `window.__chalkEditor` (tldraw Editor) and `window.__chalkBoard` (the `WhiteboardHandle`) are exposed on the session and `/dev/board` pages. `/dev/board?demo=marks` replays point/ring/erase.

## Session recording and admin replay (Sept 15 2026)
Mateo wants every beta session recorded in detail, so the two of us can find where the tutor goes wrong. It is on for every user; only his account can look.
- **The recorder.** `lib/session-recorder.ts` runs on the session page.
  - **What it records.** Every debug event from the live client and the page arrives as `live.debug`. That covers each tool call with its arguments, result and duration (including `check_answer` and `record_attempt`), interruptions, turn ends, "[Tutor state]" lines, reconnects, go-aways and errors. It also records `tool.call` for board tools, `tutor.speaking` on and off, `tutor.activity`, `session.started` (provider, speech rate, viewport, user agent), `settings.speed` and `board.frame`. These sit alongside the existing `transcript.entry`, `whiteboard.snapshot` and `session.*` events.
  - **How events are sent.** Events are batched to `POST /api/sessions/[id]/events` (body `{ events }`) every 1.5 s or 40 events, and handed to `sendBeacon` when the page hides. Failures are dropped after three tries and never disturb the session.
  - **Board pictures.** The recorder keeps the exact JPEG sent to Gemini after each drawing. Providers without automatic pictures get one 1.2 s after a board tool call instead, and there is a last one at session end (capped at 2.5 s). They go to `POST /api/sessions/[id]/frames` and are stored once per session by SHA-1 in `session_frames` (base64 in Postgres, about 20–30 KB each).
- **What the tutor "thinks" is not available.** Gemini Live (`gemini-3.1-flash-live-preview`) accepted `thinkingConfig.includeThoughts` but returned no thought parts on a test turn (Sept 15 2026). Tool calls with their results and the tutor-state lines are the closest record of why it acted.
- **Database.** `session_frames` is created by `lib/db/sql/2026-09-15-session-frames.sql`, which is additive and idempotent. There is no migrations folder, so run that file on any new database. When it was added, the Neon database held 14 MB.
- **Admin pages.** `/admin` lists every session with student, length, talk, tool calls, issue chips and picture count. `/admin/sessions/[id]` is the replay.
  - **Access.** `lib/admin-emails.ts` allows msosaalbrecht@gmail.com, plus the QA account in development only. `getAdminSession()` in `lib/admin.ts` guards every page and route, and anyone else gets a 404. The sidebar shows "Recorded sessions" to admins.
  - **The replay.** It shows stats, the board picture at the playhead, and a timeline with lanes for student speech, tutor voice, actions, board pictures and issues. Playback runs at 1×, 2×, 4× or 8×, with Space and arrow keys. A searchable, filterable log sits beside it, and clicking a row seeks.
  - **Exports.** `/api/admin/sessions/[id]/export?format=md|json` gives a Markdown timeline for close reading, or everything as JSON.
- **Analysis.** `lib/session-recording.ts` is pure and unit-tested. It:
  - merges transcription fragments into utterances;
  - counts tool calls without double counting;
  - finds failed tools, interruptions, reconnects, errors, silences of 20 s or more, and approximate reply times;
  - builds the log and the Markdown export.

  Sessions from before the recorder show their transcript only.
- **Free QA without a live tutor.** Sign in with `/api/dev/qa-login?to=/admin`. Create a session with `POST /api/sessions`, send a synthetic `{ events }` batch and a few real board pictures (`window.__chalkBoard.exportImage(896)` on `/dev/board`) through the real routes. Open the replay, then `DELETE /api/sessions/[id]`, which cascades to events and pictures. Background tabs do not run animation frames, so bring the replay tab to the front before testing playback.
- **Privacy.** Beta testers may be minors. Students and parents should know sessions are recorded, and the privacy notice should say so.

## Graphs: Desmos (Sept 15 2026)
Mateo found the old graphs "not good" (a fixed 300 × 220 box, numbers only at the four ends, 121 straight segments, a steep curve flattening the rest, and plain writing like "3x − 2" or "|x|" drawing "Could not read that expression" while the tool told the tutor it had graphed it). He compared Desmos, JSXGraph and Mafs side by side on the board and chose Desmos. The comparison page and the other two libraries were removed.
- **What draws.** `add_function_graph`, `plot_points` and `add_coordinate_axes` create a `graph` shape (`components/board/GraphShape.tsx`, 420 × 315 plus a 14px credit strip; three fit across a laptop board page, 480 × 360 fitted two). Its picture is an SVG made by one hidden Desmos calculator (`components/board/desmos-renderer.ts`, `asyncScreenshot` with `format: "svg"`, about 8–25 ms a graph once Desmos has loaded; the script is 4.3 MB and loads with the first graph, never on pages without one). The shape keeps the graph spec (JSON) and the SVG: crisp at any zoom, saved with board snapshots, wiped in by the writing animation like typeset math. Board pictures for Gemini wait for graphs still rendering (up to 8 s), `toSvg` renders on demand, and a resumed board redraws graphs saved before their picture arrived.
- **`lib/desmos-graph.ts`** (pure, unit-tested) builds the spec. `toDesmosLatex` rewrites plain math Desmos rejects (checked against Desmos: `sqrt(x)`, `abs(x)`, `|x|`, `sin(x)`, `x²`, `e^(-x)`, `x^-2`, `pi`, the Unicode minus) into LaTeX. `graphLatexProblem` uses Compute Engine to refuse structurally broken input up front (an unclosed brace), so the dispatcher returns an error the tutor can fix in the same turn; Desmos's own per-expression errors arrive after rendering and show in `[Board: …]` as "[could not draw: …]". `graphFunction` samples curves with Compute Engine 0.128, whose `compile()` is a free function returning `{ success, run }` (older versions had `expr.compile()`). `autoYRange` trims the far 4% tails so an asymptote cannot flatten a curve; `fitBounds` squares the units only when the ranges are already within 1.5× of square (so the x range the tutor asked for survives), and a circle always gets square units with its y range derived from x. Crossings of two curves are found numerically and labelled; the slope triangle is two dashed restricted lines with "run"/"rise" labels on points of size 0.01 (a point with `pointOpacity: 0` also hides its label in Desmos's SVG); joined points are an `\operatorname{polygon}`. Labelled points keep math coordinates, so `highlight(target, text: "vertex")` dabs the point itself.
- **The tool.** `add_function_graph` accepts LaTeX or plain math and gained `y_min`, `y_max` and `extra_expressions` (shaded inequalities, circles, vertical lines, restricted pieces, up to 6, separated by ";").
- **Licence and key.** Commercial use of the Desmos API needs a Desmos partnership (partnerships@desmos.com) and its key in `NEXT_PUBLIC_DESMOS_API_KEY`. Development falls back to the public demo key from Desmos's own docs, which is for local use only. A production build without a key, or a session where Desmos fails to load, draws graphs the old vector way. Images made with Desmos tools are CC-BY-SA with attribution, hence the small "desmos" credit under each graph.

## GPT-Live protocol facts we verified (do not relearn these)
1. The Live model's clock is driven by **inbound audio**. With no mic track nothing happens: appended context is never injected and the model never speaks. Text-only QA sessions send faint synthetic room tone (`createSyntheticMicStream`).
2. `session.instructions.append` alone never makes the model speak. `session.commentary.append` does (a near-verbatim paraphrase within ~1 s). The greeting and the resume line are sent as commentary.
3. Client-triggered backend turns work: `response.item.create` (user message or attachments) + `response.create` → the Live service creates a delegation, the voice model bridges ("let me put that on the board"), then speaks the backend's text. Typed messages and file uploads use this path.
4. Tool loop: nested `response.output_item.done` (`function_call`) → execute on the board → `response.item.create {function_call_output}` → after the nested `response.completed`, send exactly one `response.create`.
5. Sessions expire after about 2 hours (`expires_at` in `session.started`). Voice and voice instructions are immutable per session; backend settings can change with `session.update`.
6. The voice model cannot see images. Photos and PDFs go to the backend as `input_image` / `input_file` items.
7. The SDK (`openai@7.15`) has typed Live events in `node_modules/openai/resources/live/live.d.ts` and a WebSocket client (`openai/resources/live/ws`) that is handy for Node probes.

- **The tiles show photographs of the real board.** `scripts/landing-shots.mjs` (needs the dev server and Chrome) replays each scene in `lesson.ts` on `/dev/landing?scene=…` (dev only, behind QA login), trims to the drawn pixels at 2x, writes `public/landing/*.png` and `components/landing/shots.generated.ts` (sizes for `next/image`). Rerun it whenever a board renderer changes. `Fragments.tsx` has `BoardShot` (photo written in from the top), `Transcript` (the app's `TranscriptList` in the sheet's chrome) and `DockBadge` comes from `VoiceDock.tsx`; `FilesPanel` (the Files popover body) is exported from `FilesPopover.tsx` for the worksheet tile. `proxy.ts` lists `/landing` as a static path so the image optimizer can fetch the photos.
- Reduced motion: every landing component reads the preference through `useReduce()` in `useScript.ts`, which returns null until hydration (Motion's own hook knows the answer on the client's first render and the server does not, which was a hydration error under reduced motion). `useScript` treats reduced motion as "final frame".
- `DitherWave` reads every prop on each frame through refs, so the tuner changes it live without rebuilding the program; its clock advances by speed per frame, so a speed change never jumps the field, and `lightness` shifts the tone (0 keeps the calibrated look). It has two patterns: `bands` (default, no longer used by the hero) and `swirl` (fbm warped by itself twice, used on sign-in and behind the landing hero through the shared preset `components/landing/swirl.ts`), plus an optional `deepColor` third tone. The swirl samples noise five times per pixel with 4 octaves and is tuned to be mostly colour with a little background (the field's value runs through four breakpoints on a deepest blue, light blue, background ramp, with slow circular drifts that loop seamlessly every four minutes (`circ()` paths in the shader, clock wrapped at 84 units by `SWIRL_LOOP`), so large soft shapes move on instead of parking in a corner and the look never drifts; straight-line drifts grew without bound, and after tens of minutes the noise lost GPU precision and the panel washed out; the sign-in panel draws seven shades so broad areas show soft gradations; the breakpoints were fitted over one full loop to the seven-shade mix of the opening minutes, so every moment matches how it starts (mean lightness about 139/255, about 3% white), with the top one high so only the brightest peaks turn white; contour-band ribbons were tried and rejected as too busy and too white, and shrinking the shapes removed little patchiness while adding detail; on sign-in the deepest tone is the voice deep blue pulled 40% toward the voice light blue; the wordmark on the panel is white, and a `calmSpot` fade anchored at the bottom-left corner (420 by 230px, cap 0.55) keeps that corner blue and never white; a small oval centred on the wordmark read as a floating pill); it pauses off screen like the bands.
- Own tokens under `.lp` in `app/globals.css` (off-white / off-black / light gray + sky accent). Buttons are `.lp-btn`: white face, 2px ink border, solid offset shadow that the face slides into on hover. Radius rule: 10px interactive, 20px surfaces, `.lp-frame` = double border.
- Fonts via `next/font` in `components/landing/fonts.ts`: Schibsted Grotesk (display), Hanken Grotesk (body), Shantell Sans (board handwriting, the same face tldraw uses), Sora (the wordmark). **Brand rule:** the word "chalk" beside the mark is always Sora at weight 650 with -0.04em tracking, via `.lp-brand` (`Wordmark`, the sidebar header, the sign-in panel). The mark is always the plain sky scribble `ChalkMark`, never the old ink tile: `Wordmark` (landing header and footer) renders it at 1.45x the text size, the same proportion as the sidebar.
- Registries in `components.json`: shadcn (base-nova style, Base UI), `@magicui`, `@animate-ui`, `@react-bits`, plus `@reactbits-starter` / `@reactbits-pro` which need `REACTBITS_LICENSE_KEY` in `.env.local` before `npx shadcn add @reactbits-pro/faq-2` or `@reactbits-starter/dither-wave-tw` will install. 21st.dev now requires an account for its registry.

## Environment (`.env.local`)
`OPENAI_API_KEY` (required), `DATABASE_URL`, `AUTH_SECRET`, `NEXT_PUBLIC_TLDRAW_LICENSE_KEY`. Optional: `OPENAI_TUTOR_BACKEND_MODEL` (default `gpt-5.6-terra`; `gpt-5.6-luna` is ~10x cheaper), `OPENAI_TUTOR_REASONING_EFFORT` (default `low`). Vercel needs the same variables in BOTH the Preview and Production environments (the Preview environment was missing `DATABASE_URL`, `AUTH_SECRET`, and the tldraw key, which is why every branch deploy failed). The DB client no longer throws at build time when the variable is missing; the first query fails instead. Gemini: `GEMINI_API_KEY` (server only). `/api/live-token` falls back to `NEXT_PUBLIC_GEMINI_API_KEY`, which Vercel Production still carries from the browser-side era; once `GEMINI_API_KEY` is set on Vercel, remove the public one and rotate the key. `NEXT_PUBLIC_TUTOR_PROVIDER` picks the default provider (see "Voice provider switch"). `NEXT_PUBLIC_DESMOS_API_KEY` is the Desmos partnership key for graphs (see "Graphs: Desmos"); without it production draws the old vector graphs.

## Gotchas
- Branch order: `gpt-live` > `v2` > `main`. Never base work on `main`.
- Background agents must not run `git checkout` / `switch` / `stash`; one did during a read-only audit and moved the working tree to `main`.
- `.playwright-mcp/` is gitignored; Playwright MCP writes screenshots and snapshots there.
- Turbopack sometimes keeps serving a stale `globals.css` after an edit (the class you just added is missing from the served stylesheet). Fix: stop the dev server, `rm -rf .next`, start it again.
